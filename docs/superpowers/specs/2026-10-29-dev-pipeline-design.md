# 개발 흐름 설계 — 찌부씰 · Subway Seal

작성일: 2026-10-29

## 의도

ID304 팀원 전원이 Figma 디자인을 코드로 옮기고, 각자 아이폰에서 직접 그려보며 확인하는 개발 흐름을 만든다.
팀원 다수가 앱 개발 경험이 적으므로 **설치와 작업 규칙이 단순해야 한다.**

## 목표

- 팀원 누구나 README만 보고 개발 환경을 세팅하고 아이폰에서 앱을 열 수 있다.
- Figma 프레임을 Claude + Figma MCP로 React 컴포넌트로 거의 그대로 옮길 수 있다.
- 첫 MVP: 터치 드로잉 캔버스.

## MVP 기능 (그리기만)

| 기능 | 내용 |
|---|---|
| 펜 | 한 종류. 손가락 터치로 그림 |
| 색상 | 색상휠: 각도 = 색상(hue), 중심→바깥 = 채도(saturation), 중심은 흰색 |
| 두께 | 조절 가능 |
| undo / redo | 획 단위 |
| 지우개 | 문지른 부분만 지움 (픽셀 지우개) |
| 그림 영역 | **정사각형** (나중에 씰이 됨). 화면 폭에 맞춤 |
| 화면 방향 | **세로만** |

- 저장·씰 만들기·스티커북은 그리기 완성 후 다음 단계. MVP에서는 새로고침하면 그림이 사라져도 된다.
- **디자인 없음:** 확정 디자인이 아직 없으므로 MVP는 기능 테스트용. 흰색/회색 박스 + 텍스트만으로 UI를 만든다. Figma 디자인은 확정 후 입힌다.
- **밝기 (Claude 결정):** 색상휠만으로는 검정·어두운 색을 만들 수 없어 기능 테스트가 불편하므로, 휠 옆에 밝기 슬라이더를 임시로 둔다. 디자인 확정 시 유지·제거 결정.

## 비목표

- 네이티브 iOS 앱(Swift/Xcode), App Store/TestFlight 배포, Apple 개발자 계정
- 안드로이드·데스크톱 브라우저 대응
- 외부 사용자 테스트, 서버, 로그인, 저장
- CI·자동 배포

## 실패로 간주할 것

- 경험 없는 팀원이 세팅 단계에서 막혀 아이폰에서 앱을 못 여는 것
- 아이폰 Safari에서 그릴 때 화면이 스크롤되거나 확대되는 것 (그리기 경험이 깨짐)
- `main`이 빌드 깨진 상태로 남아 팀원 전원이 막히는 것

## 제약

- 대상: **iPhone Safari만.** 팀원 전원 아이폰 + 맥 보유.
- 테스트: 팀 내부만. 각자 맥에서 개발 서버를 띄우고 아이폰으로 접속.
- 협업: 팀원 전원이 같은 레포 `main` 브랜치에 직접 커밋·푸시.
- 레포: https://github.com/WooeeKim/subwayseal — 커밋·PR에 Claude 공동저자 표기 금지.
- Figma 변수(디자인 시스템)는 나중에 정리 예정.

## 정한 것

### 기술 스택 (Claude 결정, 팀 동의)

- **Vite + React + TypeScript + Tailwind CSS**
  - Figma Dev Mode / Figma MCP의 기본 출력이 React + Tailwind라 옮기기 쉬움.
- 그리기는 브라우저 기본 **Canvas API** + Pointer Events. 드로잉 라이브러리 없음.
- React는 UI(툴바, 색상휠, 두께)만 담당. 캔버스 픽셀은 React 상태로 다루지 않음.

### 실행·테스트 흐름

1. 각자 맥에서 `npm run dev -- --host` (Vite가 같은 네트워크에 공개)
2. 아이폰을 맥과 같은 Wi-Fi에 연결, Safari에서 `http://<맥 IP>:5173` 접속
3. 코드 저장 시 아이폰 화면 자동 갱신
4. 학교 Wi-Fi가 기기끼리 접속을 막으면: 아이폰 개인용 핫스팟에 맥을 연결하고 같은 방식으로 접속

### Git 작업 규칙

- 브랜치·PR 없음. 모두 `main`.
- 작업 시작 전, 푸시 직전 `git pull --rebase`
- 푸시 전 `npm run build` 통과 확인 (타입 검사 + 빌드)
- 한 사람이 한 컴포넌트 파일을 맡아 같은 파일 동시 수정 피하기

### 컴포넌트 분담 단위

`DrawingCanvas`, `ColorWheel`, `BrushSize`, `Toolbar`(undo/redo/지우개 버튼). 획 기록(undo/redo 스택)은 캔버스와 툴바가 공유하는 상태.

**순서 (Claude 결정):** 팀이 나눠 작업하기 전에 한 명이 먼저 뼈대를 `main`에 올린다 —
Vite/React/TS/Tailwind 세팅, 공유 상태(현재 색·두께·도구, 획 목록, undo/redo) 인터페이스, 빈 컴포넌트 4개.
그 뒤 팀원이 컴포넌트를 하나씩 맡는다. `App.tsx`, `package.json`, 공유 상태 파일은 바꿀 때 팀 채팅에 먼저 알린다.

**Figma → 코드 (Claude 결정):** Claude Code + Figma 연결은 필수 세팅이 아니다. README 세팅만으로 개발 가능해야 하고, Figma 옮기기는 Claude를 쓰는 팀원이 맡는다.

### 디자인 토큰 자리

Figma 변수가 정리되면 Tailwind 테마(`@theme`의 색·간격·폰트)에 1:1로 옮긴다. 그 전까지는 임시 값 사용.

## 구현자에게 맡기는 것

- 폴더 구조, 파일 이름
- 획 데이터 구조, undo/redo 구현 방식 (획 목록 다시 그리기 vs 스냅샷)
- 픽셀 지우개 구현 방식 (배경색 덧칠 vs `destination-out`). 씰은 배경이 투명해야 하므로 `destination-out` 권장
- 두께 조절 UI 형태, 범위
- 색상휠 구현 방식 (canvas vs CSS conic-gradient)
- iPhone Safari 대응 세부: `touch-action: none`, 더블탭 확대 방지, `devicePixelRatio` 선명도, 노치·홈바 여백(`viewport-fit=cover`)
- 패키지 버전 (작성 시점 안정 버전)

## 변경 사항 (2026-10-30) — 팀 확인 필요

위 MVP 범위를 넘어 아래가 먼저 들어갔다. 위 본문은 처음 합의한 기록이라 그대로 두고, 바뀐 점만 적는다.
팀이 동의하지 않는 항목은 되돌리거나 다시 정한다.

### 범위

| 처음 정한 것 | 지금 코드 |
|---|---|
| MVP는 그리기만. 저장·씰·스티커북은 다음 단계 | 저장, 스티커북, 지하철 꾸미기까지 들어감 |
| 비목표: 서버, 로그인, 저장 | **Supabase**(DB + 이미지 저장소)로 저장. 로그인은 여전히 없음 |
| 비목표: 데스크톱 브라우저 대응 | PC에서는 폰 비율(402×874) 틀로 가운데 보여 줌. 확인용이며 대상은 여전히 iPhone Safari |
| 디자인 없음, 흰/회색 박스 | Figma UX 파일의 132:* 프레임을 그대로 옮김 |

### 기능

| 처음 정한 것 | 지금 코드 | 이유 |
|---|---|---|
| 색상휠 + 임시 밝기 슬라이더 | 색 10개 팔레트 (색 버튼을 누르면 뜸) | Figma 툴바에 색상휠이 없고 색 버튼 하나만 있음 |
| 펜 한 종류 + 두께 조절 | 연필·지우개 + 두께 5단계 | Figma 툴바 그대로 |
| undo / redo (버튼) | 두 손가락 탭 = 실행 취소, 세 손가락 탭 = 다시 실행 | Figma에 버튼 자리가 없음 |
| 그림 영역 정사각형 | Figma 카드 비율(361×451) 안의 점선 영역 | Figma 디자인 그대로 |
| 새로고침하면 사라져도 됨 | DB에 저장. 키가 없으면 메모리에만 저장하고 "DB 미연결" 표시 | — |

라벨 6개는 스티커북 6권으로 정했다. Figma에서 스티커북 라벨 색과 지하철 꾸미기 기본 선택 라벨(4번)이 같아서다.

### 컴포넌트 분담

처음 정한 4개(`DrawingCanvas`, `ColorWheel`, `BrushSize`, `Toolbar`) 대신 지금은 이렇게 나뉜다.
나눠 맡을 때 이 단위를 쓴다.

- `src/screens/` — 화면 4개: `Splash`, `CanvasScreen`, `StickerBookScreen`, `SubwayDecoScreen`
- `src/components/` — `DrawingCanvas`, `Toolbar`(도구·두께·색 포함), `StickerFrame`·`StickerCard`(씰 카드), `TopTabs`, `GridBackground`
- `src/lib/` — 공유 파일: `stickers.ts`(DB 읽기·쓰기), `labels.ts`, `supabase.ts`. **바꿀 때 팀 채팅에 먼저 알린다** (`App.tsx`, `package.json`과 같음)
- `supabase/` — DB 구조. 바꿀 때는 `migrations/`에 새 번호 파일을 추가하고 DB 관리자가 실행한다

### 남은 것

- 라벨(책) 이름·의미는 아직 없음. 색으로만 구분
- 지하철 사진 `subway.png`가 2.6MB라 첫 로딩이 느림
- 누구나 읽고 쓸 수 있는 DB 권한(anon). 팀 밖으로 공개하기 전에 다시 정해야 함
